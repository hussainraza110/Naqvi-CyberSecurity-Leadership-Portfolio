# Crisis & Resilience KPI / KRI Framework

> Targets below are illustrative; set actual thresholds using risk appetite and service impact analysis.

| Metric | Type | Example target | Owner | Evidence |
|---|---|---|---|---|
| Crisis roles with current primary/alternate coverage | KPI | ≥95% | Crisis Manager | Roster validation |
| Activation time after defined trigger | KPI | Within approved objective | Crisis Manager | Timeline/log |
| Critical services with current cyber recovery test | KRI | 100% in cycle | COO/service owners | Test records |
| Tests meeting RTO/RPO and business validation | KRI | 100% or approved exception | Service owner | Test evidence |
| Recovery assets with independently validated integrity | KRI | 100% in scope | CIO | Integrity reports |
| Material crisis actions overdue beyond tolerance | KRI | 0 | Action owners | Action register |
| Stakeholder updates within agreed cadence | KPI | ≥95% | Communications | Message log |
| Exercise objectives achieved | KPI | Improve against baseline | CISO/facilitator | Evaluation |

Define population, source, cut-off, calculation, owner, frequency, limitations, and breach response. Distinguish elapsed time from business-impact duration. A tabletop is not technical recovery proof.
